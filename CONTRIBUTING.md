# Contributing to Emaki

Thank you for helping. Emaki is young (beta), so every bug report counts.

## Who decides

Emaki was founded and is led by Arthur Yakymenko; he has the final say. As the project grows, maintainers will join.

## Reporting a bug

- Search the existing issues first; if yours is there, add what you see to it.
- Open a new issue with the **Bug report** form. Include the Emaki version (Settings › About), your hardware, what
  you did and what happened. The **Report a problem** app collects the details about your system; attach its report.
- A security problem never goes into a public issue: see [SECURITY.md](SECURITY.md).

## Suggesting an idea

Open an issue with the **Idea** form. For anything big — a new component, a change to how Emaki looks or to its
defaults — open the idea first and wait for an answer before you write the code.

## Sending a change

- One pull request, one change.
- Run `make check` before you send it; it must pass.
- Code, comments and commit messages are in English.
- Sign off every commit: `git commit -s` adds `Signed-off-by: Your Name <you@example.com>`. By signing off you
  certify the [Developer Certificate of Origin](https://developercertificate.org/): you wrote the change, or you
  have the right to submit it under the project's licence.
- You are responsible for your change and should be able to explain every line of it.
- After installation Emaki never writes to a person's own configuration files; a change that does is not accepted.
